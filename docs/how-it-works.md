# 동작 방식

v4(현재) 기준입니다. 흐름도는 [flow.html](flow.html)에 있어요.

## 흐름

```
cron-job.org (15분마다) → GitHub Actions daily.yml
  └─ python -m app cycle
       ├─ sources.py   왓딜 API · 루리웹 · 클리앙에서 최근 24시간 딜 읽기
       ├─ store.py     SQLite에 기록 (같은 딜은 묶고, 이미 본 딜은 댓글 수만 새로)
       ├─ matcher.py   새 딜 ↔ 관심사 → notifier.post_alert (스레드 + DM)
       ├─ mentions.py  핫딜 thread의 새 @멘션 → nl.py(Gemini) → commands.py
       └─ ranking.py   12시: 인기·게임·IT·식품 TOP 5, 21시: 인기 TOP 5 → notifier.post_board
```

상태는 `data/sallae.db`와 `data/board.json`이고, Actions 캐시로 다음 실행에 넘깁니다.

## 출처

GitHub Actions는 미국 데이터센터 IP라 여러 사이트가 막습니다 (2026-10-11 Actions에서 직접 시험).

| 사이트 | Actions에서 | 비고 |
|---|---|---|
| 왓딜 `whatdeal.kr/api/deals` | ✅ | 뽐뿌·펨코·아카라이브·퀘이사존·어미새 등 새 딜, 댓글 수·상품 링크(`product_url_key`)·카테고리. 왓딜 자체 '인기순'은 사이트 안 클릭 수라 쓰지 않음 |
| 루리웹 핫딜, 클리앙 알뜰구매 | ✅ | 목록을 직접 읽어 추천·조회 수까지 |
| 뽐뿌 RSS, 어미새 | ✅ | 지금은 왓딜로 받음 |
| hotdeal.zip, 알구몬 | ❌ | Cloudflare / Turnstile. 일반 요청·크롬 흉내·헤드리스·실제 창 모두 막힘 |
| 펨코(RSS·모바일 포함), 퀘이사존, 아카라이브, 쿨엔조이 | ❌ | 직접은 막힘 → 왓딜로 받음 |

- 매 실행 하루치를 다시 읽어 댓글 수를 최신으로 맞춥니다 (요청 약 6번, 사이트마다 1.5초 간격).
- 한 출처가 실패해도 나머지로 계속합니다. 왓딜이 막히면 루리웹·클리앙만 남습니다.

## 순위 (`ranking.py`)

- **점수:** 커뮤니티 안에서 댓글(추천) 수가 상위 몇 %인지 60% + 댓글 절대 수 40%. 댓글이 많은 펨코가 위로 오는 편입니다 (일부러 그렇게 둠). 여러 커뮤니티에 같이 올라오면 곳마다 +0.12.
- **같은 딜:** 원문 주소나 상품 링크(`product_key`)가 같거나, 제목이 거의 같거나 가격이 같고 제목이 비슷하면 한 줄 (`dedupe.py`).
- **같은 행사:** 같은 커뮤니티·쇼핑몰(쿠팡=쿠팡와우)·카테고리에서 30분 안에 비슷한 가격으로 올라온 딜은 대표 한 줄에 "외 n개 같은 행사".
- **빼는 것:** 종료된 딜, 제목의 기간 `(~10/10)`이 지난 딜, 그 게시판에 2일 안에 올린 딜, (카테고리 글) 오늘 인기에 이미 나온 딜.
- 범위: 인기 최근 16시간, 카테고리 최근 24시간. 카테고리는 왓딜 분류(game·digital·food)와 루리웹 말머리를 씁니다.

## 게시판 글

| 게시판 | 시각 (KST) | 맨 아래 버튼 |
|---|---|---|
| 🔥 인기 | 12시 · 21시 | hotdeal.zip 인기 더 보기 |
| 🎮 게임 · 💻 IT · 🍜 식품 | 12시 | 알구몬 ○○ 랭킹 더 보기 |

- 카드: 딜마다 순위·제목(원문 링크) / 가격·쇼핑몰 / 출처·💬댓글·👍추천, 오른쪽에 상품 사진 (Components V2).
- Actions가 늦게 돌아도 그 시각부터 3시간 안이면 올리고, 시간대마다 한 번만 올립니다 (`meta`의 `posted:게시판:날짜-시`).

## 관심사 알림

- **키워드 관심사:** 키워드의 단어가 제목에 모두 있으면 (`matcher.py`)
- **설명형 관심사:** 새 딜 목록과 함께 Gemini에 한 번 물어 판단 (`nl.judge`, 기본 `gemini-3.5-flash-lite`). 실패하면 키워드만.
- 같은 딜은 한 번만, 이미 알린 딜은 가격이 내려가면 다시. 같은 딜에 여러 사람이 걸리면 메시지 하나로.
- 핫딜 thread에 조용히 올리고(대상자만 태그), 대상자에게 DM으로 링크. 카드에 사진·가격·이유와 "보러 가기"(쇼핑몰)·"원문 보기" 버튼.

## @멘션

상주 봇 없이, 실행할 때마다 핫딜 thread의 지난번 이후 메시지를 읽어 봇을 부른 말에 답합니다 (`mentions.py`). 봇을 멘션한 메시지는 Message Content 권한 없이도 내용을 읽을 수 있습니다.

- Gemini가 말을 도구 호출로 바꿉니다 (`nl.parse_command`): `add_watch`, `remove_watch`, `list_watch`, `search_deals`.
- 마지막으로 읽은 메시지 ID를 하나씩 기록해서, 중간에 실패해도 같은 말에 두 번 답하지 않습니다. 처음엔 위치만 잡고 지난 메시지에는 답하지 않습니다.
- 등록·해제 때 고정 메시지 **🔔 알림 키워드**를 고칩니다 (`board.py`, 메시지 ID는 `data/board.json`).

## 운영

- 실행 기록: GitHub Actions의 `daily` 워크플로 (공개 레포라 로그도 공개. 비밀값은 가려짐)
- 수동 실행: `gh workflow run daily.yml --ref main`
- 캐시가 사라지면: 알림 목록은 `SEED_JSON`에서 복원, 딜·올린 글 기록은 새로 시작 (첫 실행은 기록만)
- 알림 목록을 바꾼 뒤 캐시가 사라질 일에 대비하려면 `python -m app export-seed`로 `SEED_JSON`을 갱신
