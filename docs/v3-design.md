# v3 설계

> 상태: 구현 중 (2026-10-09). 0단계 진행, 1·2·4단계 완료, 결정한 내용은 [결정 사항](#결정-사항)에 있습니다.

## 목표

1. **관심사 알림.** 친구가 등록한 관심사에 맞는 딜이 올라오면 그 사람을 태그해 알린다.
2. **자연어로 쓰기.** 명령어를 외우지 않고 `@살래말래 게이밍 모니터 핫딜 뜨면 알려줘`처럼 말하면 된다.
3. **소스 넓히기.** 알구몬 3개 카테고리에 안 나오는 딜(네이버페이 할인 등)도 잡는다.
4. 같은 자연어 구조를 imposter-finder에도 붙인다.

매일 12:00 TOP 10 게시는 유지하되, 소스를 hotdeal.zip 인기로 바꿉니다.

## 구조

```
launchd (KeepAlive)
  └─ python -m app serve                       상주 프로세스 1개
       ├─ Discord gateway        @멘션 메시지 수신 → nl → 결과 답장
       ├─ nl.py                  Gemini 호출 (메시지 → 동작, 딜 ↔ 관심사 판단)
       ├─ scheduler
       │    ├─ 매일 12:00        hotdeal.zip 인기 TOP 10 게시 (실패 시 1시간 뒤 재시도)
       │    └─ 60분마다          hotdeal.zip 새 딜 수집 → 관심사 매칭 → 태그 알림
       ├─ hotdealzip.py          TOP 10·매칭용 수집
       ├─ collector.py           알구몬 카테고리 랭킹 (요청 시)
       ├─ matcher.py             키워드·가격 매칭, 같은 딜 묶기
       ├─ people.py              이름·별명 → Discord ID
       └─ store.py               SQLite (data/sallae.db)
```

- **상주로 바꾸는 이유:** `@멘션`에 바로 답하려면 Discord gateway에 계속 연결돼 있어야 합니다. imposter-finder의 `serve`와 같은 방식(`KeepAlive`)입니다.
- **Chrome 접근은 한 번에 하나씩.** 수집 작업이 겹치지 않게 lock을 걸어 탭이 동시에 여러 개 열리지 않게 합니다.
- **알림 위치:** 핫딜 고정 thread에 댓글로 보내고, 대상자를 `<@discord_id>`로 태그합니다.

## 관심사 알림

### 등록할 수 있는 것

| 종류 | 예시 | 매칭 방법 |
|---|---|---|
| 상품명 + 가격 | "에어팟 프로 25만원 이하" | 단어 매칭 + 가격 비교 |
| 설명형 | "괜찮은 OLED 모니터 혹은 게이밍 모니터" | Gemini 판단 |
| 다른 사람 대신 | "게이밍 모니터 뜨면 진호한테 알려줘" | 위와 같고 대상자만 다름 |
| 한 번만 | "한 번만 알려줘" | 첫 알림 후 자동 해제 |

등록할 때 Gemini가 문장에서 `want`(설명), `keywords`(정확한 상품명이 있으면), `max_price`, 대상자, `once`를 뽑습니다.

### 데이터 (SQLite, `data/`는 커밋하지 않음)

```sql
CREATE TABLE watches (
  id           INTEGER PRIMARY KEY,
  owner_id     TEXT NOT NULL,      -- 알림 받을 사람 Discord ID
  created_by   TEXT NOT NULL,      -- 등록한 사람 Discord ID (대신 등록하면 다름)
  want         TEXT NOT NULL,      -- 원문 설명, 예: "괜찮은 OLED 모니터 혹은 게이밍 모니터"
  keywords     TEXT,               -- JSON 배열, 정확한 상품명일 때만. 예: ["에어팟 프로"]
  max_price    INTEGER,            -- 원, NULL이면 가격 무관
  once         INTEGER NOT NULL DEFAULT 0,
  active       INTEGER NOT NULL DEFAULT 1,
  created_at   TEXT NOT NULL
);

CREATE TABLE deals (
  source       TEXT NOT NULL,      -- algumon / hotdealzip
  deal_id      TEXT NOT NULL,
  group_key    TEXT NOT NULL,      -- 같은 딜(크로스포스트)을 묶는 키
  title        TEXT NOT NULL,
  price        INTEGER,            -- 숫자로 못 바꾸면 NULL
  url          TEXT NOT NULL,
  first_seen   TEXT NOT NULL,
  PRIMARY KEY (source, deal_id)
);

CREATE TABLE notified (
  watch_id     INTEGER NOT NULL,
  group_key    TEXT NOT NULL,
  price        INTEGER,            -- 알렸을 때 가격 (가격 인하 재알림 판단용)
  notified_at  TEXT NOT NULL,
  PRIMARY KEY (watch_id, group_key)
);
```

### 매칭 (60분마다)

1. 새로 수집한 딜을 `deals`에 넣고, 기존 중복 제거 로직(제목 유사도 + 같은 가격)으로 `group_key`를 정합니다. 여러 커뮤니티에 올라온 같은 딜은 하나로 묶입니다.
2. **`keywords`가 있는 관심사:** 제목과 키워드를 `_normalised_title`로 정규화하고, 키워드의 단어가 모두 들어 있으면 매칭합니다. "에어팟 프로"는 "에어팟 4세대"와 매칭되지 않습니다.
3. **설명형 관심사:** 새 딜 목록과 설명형 관심사 전체를 **한 번의 Gemini 요청**으로 넘겨 맞는 조합과 이유를 받습니다. 관심사나 딜이 늘어도 수집 1번당 요청 1번입니다.
4. `max_price`가 있으면 가격을 비교합니다. 달러나 "가격별상이"처럼 숫자로 못 바꾸는 가격은 알림에 "(가격 확인 필요)"를 붙입니다.

### 알림 규칙

| 상황 | 동작 |
|---|---|
| 같은 딜이 여러 커뮤니티에 올라옴 | `group_key`로 묶어 1번만 알림 |
| 이미 알린 딜의 가격이 내려감 | 다시 알림 ("가격 인하") |
| `once` 관심사가 알림을 받음 | 자동 해제 |
| 같은 상품의 새 딜 (다른 쇼핑몰, 다음 주 등) | 다시 알림 |

설명형 관심사는 알림이 많아질 수 있습니다. 실제로 써보고 많으면 한 사람당 하루 알림 수 제한이나 하루치 묶음 알림을 넣습니다.

```
@진호 🔔 게이밍 모니터 — LG 울트라기어 27GX790A 480Hz OLED 899,000원
쿠팡 · 퀘이사존 · https://...
💬 고사양 OLED 게이밍 모니터라 조건에 맞아요
```

### 다른 사람 대신 등록
- "진호한테 알려줘"의 "진호"는 `people.py`가 Discord ID로 바꿉니다. 친구 목록은 imposter-finder의 `players.json`(Discord ID 포함)에 별명을 추가해 두 봇이 같이 씁니다.
- 메시지에 `@진호`처럼 Discord 멘션이 있으면 ID를 바로 씁니다.
- 대신 등록하면 대상자에게 "@진호 건우가 '게이밍 모니터' 알림을 등록해줬어"라고 알려 원치 않으면 바로 지울 수 있게 합니다.
- 모르는 이름이면 "진호가 누군지 모르겠어, @멘션으로 다시 말해줘"라고 되묻습니다.

## 자연어 인터페이스

### 흐름
1. 봇을 `@멘션`한 메시지만 처리합니다. 멘션된 메시지는 Message Content 특수 권한 없이도 읽을 수 있고, 잡담에 끼어들지 않습니다.
2. 보낸 사람, 친구 목록, 보낸 사람의 관심사 목록을 메시지와 함께 Gemini에 넘깁니다.
3. Gemini가 고른 도구를 봇이 실행하고 결과를 답장합니다. 도구가 없으면 Gemini의 짧은 답을 그대로 보냅니다.

### 도구

| 도구 | 하는 일 |
|---|---|
| `add_watch(want, keywords?, max_price?, for_user?, once?)` | 관심사 등록 |
| `remove_watch(watch, for_user?)` | 삭제. 대상자 목록에서 가장 비슷한 항목을 지우고, 애매하면 되묻기 |
| `list_watch(for_user?)` | 관심사 목록 |
| `show_deals(category)` | 오늘 TOP 목록 (`전체`/`게임`/`IT`/`식품`) |

imposter-finder에는 `pubg_stats(player, matches?)` 같은 도구를 같은 방식으로 붙입니다.

### 모델: Gemini 무료 등급
- `gemini-3.5-flash-lite`처럼 버전을 고정합니다. `-latest`는 가리키는 모델이 바뀔 수 있습니다.
- 무료 한도는 공개되지 않습니다(AI Studio에도 표시 안 됨). 429가 나면 "오늘 AI 한도를 다 썼어, 내일 다시 해줘"라고 답합니다.
- 하루 요청 예상: 매칭 24회 + 대화 수십 회.
- 무료 등급 입력은 Google 서비스 개선에 쓰일 수 있습니다. 넘기는 내용은 멘션한 메시지, 친구 이름, 관심사, 공개 딜 목록뿐입니다.
- LLM 호출은 `nl.py` 한 곳에 모읍니다. 한도가 부족하면 유료 결제를 켜거나 Claude·OpenAI API로 이 파일만 바꿉니다.

### 딜 ↔ 설명형 관심사 판단 (요청 1회, 딜 39개 · 관심사 4개, 1.6초)

| 관심사 | 고른 딜 | 판정 |
|---|---|---|
| 괜찮은 OLED 모니터 혹은 게이밍 모니터 | LG OLED 480Hz, 삼성 오디세이 G5 165Hz | ✅ 사무용 모니터는 제외 |
| 에어팟 프로 25만원 이하 | 없음 | ✅ 289,000원은 제외 |
| 배달·외식 할인 | 버거킹 와퍼 | ✅ |
| 닌텐도 스위치 관련 할인 | 없음 | ❌ 프로콘2, 스위치2 호환 SD카드를 놓침 |

모니터·에어팟 딜 4개는 판단력 확인용 가상 딜입니다. 엉뚱한 딜을 고르지는 않았지만 맞는 딜을 놓쳤습니다. 프롬프트의 "애매하면 넣지 마"를 완화하고 알림에 이유를 붙이며, 그래도 놓치면 판단용 모델만 Flash로 올립니다.

## 소스

| 용도 | 소스 | 주기 |
|---|---|---|
| 매일 TOP 10 | hotdeal.zip 인기 (`/인기`), 중복 제거 후 상위 10개 | 하루 1회 |
| "게임 핫딜 알려줘" 같은 요청 | 알구몬 카테고리 랭킹 (`/n/deal/rank?categoryId=`) | 요청 시 |
| 관심사 매칭 | hotdeal.zip 전체 최신 (`/`) + 인기 (`/인기`) | 60분 |

### 관심사 매칭은 검색이 아니라 "새 딜 훑기"
- 관심사마다 사이트를 검색하지 않습니다. 60분마다 새로 올라온 딜 목록을 한 번 가져와서, 그 목록을 모든 관심사와 대조합니다. 관심사가 늘어도 사이트 요청 수는 그대로입니다.
- 그래서 **수집한 목록에 들어온 딜만** 잡힙니다. 인기 목록만 보면 덜 유명한 딜을 놓치므로 전체 최신 목록을 같이 봅니다.
- 전체 최신 목록은 첫 화면 25개가 약 35분 분량이었습니다(2026-10-09 17:08~17:42). '더보기'로 3페이지(75개)를 읽으면 저녁 기준 약 3시간 분량(16:18~19:10)이라 60분 간격에 충분합니다.
- 결과는 맞는 딜이 있을 때만 핫딜 고정 thread에 대상자 태그와 함께 올라갑니다. 없으면 아무것도 보내지 않습니다.

### 조사할 것
- hotdeal.zip 인기의 정렬 기준, "오늘"의 범위(12:00이면 반나절치뿐인지), 카테고리 치우침(10/9: 25개 중 PC 11개)
- 시간대별 딜 수 (낮 시간에도 3페이지가 60분을 넘는지)
- 며칠간 인기 HTML을 저장해 알구몬 TOP 10과 비교

### 요청량
- 60분마다 hotdeal.zip 2~3페이지, 하루 50~75회입니다. 알구몬은 매일 TOP 10에서 빠지고 요청이 있을 때만 읽어서 오히려 줄어듭니다.
- hotdeal.zip도 Cloudflare 챌린지가 있어서 요청이 몰리면 막힐 수 있습니다. 지켜보며 간격을 조정합니다.
- 그때마다 Chrome에 탭이 몇 초씩 열립니다.

## 단계

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 0 | hotdeal.zip 인기·최신 특성 조사 (며칠간 HTML 저장) — **진행 중**, `snapshot` 하루 4번 | 알구몬 TOP 10과 비교, 시간당 딜 수 |
| 1 | `hotdealzip.py` + 매일 TOP 10을 hotdeal.zip 인기로 전환 — **완료** | fixture로 파서 테스트, DEV thread 게시 |
| 2 | `store.py` + `matcher.py` + 60분 수집, 키워드 매칭·알림 규칙. 관심사는 우선 `watch-add`로 직접 등록 — **완료** | fixture로 매칭 테스트, DEV thread 알림 |
| 3 | `serve` 상주 전환 + `@멘션` 자연어 처리 (`nl.py`, `people.py`) | DEV 채널에서 등록·조회·삭제·대신 등록 |
| 4 | 설명형 관심사 Gemini 판단 — **완료** (2단계와 함께) | 저장한 딜 목록으로 판단 결과 확인 |
| 5 | imposter-finder에 같은 자연어 구조 적용 | `/user` 대신 `@멘션`으로 전적 조회 |

### 봇을 하나로 합치는 안 (보류)
하나의 Discord 봇이 모든 멘션을 받아 LLM이 주제(핫딜/배그)를 고르고, 각 thread로 답하는 구조입니다.

- 장점: 친구들이 봇 하나만 알면 됩니다. 도구 목록만 늘리면 주제를 추가할 수 있습니다.
- 단점: 한쪽 장애가 다른 쪽을 같이 멈추고, 두 저장소를 한 프로세스로 묶어야 합니다.
- 지금은 봇 토큰도 따로라 각자 멘션을 받는 편이 단순합니다. 친구들이 "어느 봇한테 말해야 해?"를 헷갈려하면 그때 합칩니다.
